# Glass Weather for KWGT

This recreates the glass-card weather design (see the web app in this repo —
the **visual reference**) as a native **KWGT** widget.

There are two things here:

1. **`kwgt/GlassWeather.kwgt`** — an importable preset, generated by
   `kwgt/build_kwgt.py`. It's built to match a real, working KWGT **v13**
   preset schema and wires every dynamic value to Kustom's weather functions.
2. **This guide** — how to import it, what each layer is wired to, the exact
   weather-function reference, and how to tweak or regenerate it.

> **Why a generated preset and not the web app itself?** KWGT can't run
> web/React code. A KWGT widget is a tree of layers (text, shapes, progress,
> font-icons) driven by Kustom's formula language. So we emit that tree as
> `preset.json` and zip it into a `.kwgt`.

> **Honest status:** the preset is hand-authored to match the real schema and
> field names extracted from a working preset, but it could not be test-imported
> on a device here. Treat it as a strong starting point — if any single field
> looks off in the editor, the reference below tells you exactly what it should
> be, and a wrong formula only affects that one layer (it won't break the rest).

---

## 0. Prerequisite: set up a weather source (do this first)

This is the #1 reason `wi(...)` / `wf(...)` come back blank. In the **KWGT app**
(not the widget editor):

1. **Settings (gear) → Weather**.
2. Choose a provider. Recent KWGT versions use **OpenWeatherMap** (free API
   key) for forecasts, or the **Kustom Weather Plugin** from the Play Store.
3. Grant **location** permission (precise), or set a manual location.
4. Set an update interval (e.g. 1–3 hours).

Until the provider returns data, every weather field renders blank — expected,
not a bug.

---

## 1. Import the preset

1. Copy `kwgt/GlassWeather.kwgt` to your phone (any folder).
2. Add a KWGT widget to your home screen, sized to a tall phone-card shape
   (about 4×6 cells).
3. Tap it → in the preset picker, use the **import / open file** option
   (folder icon → "Open preset" or the import menu) and pick
   `GlassWeather.kwgt`.
4. Apply (the save/check icon).

If weather fields are blank, revisit **section 0**.

## 2. What's wired (layer → formula)

The widget is a `RootLayerModule` containing a rounded **Card background**
shape and a vertical **Content** stack:

| Layer (title in editor) | Content / formula                                   |
|-------------------------|-----------------------------------------------------|
| Location bar            | `place` icon + `$li(addr)$`                          |
| Currently label         | `CURRENTLY` (static)                                 |
| Condition               | `$tc(cap, wi(cond))$`                                |
| Current temp            | `$wi(temp)$°`                                        |
| Current icon            | FontIcon, mapped from `wi(icon)` (see §4)            |
| Temp gauge              | ProgressModule, level = current temp within today's low→high |
| Stats: Feels            | `$wi(flik)$°`                                        |
| Stats: Humidity         | `$wi(hum)$%`                                         |
| Stats: Wind             | `$wi(wind)$$wi(windu)$`                              |
| Week summary            | rule-based sentence from globals (see §3)            |
| Forecast day 0–6        | weekday + icon + `$wf(max,N)$°` / `$wf(min,N)$°`     |

Globals (`wet`, `warm`, `cool`, `trend`) hold the summary's computed numbers so
the summary text stays readable.

---

## 3. Weekly summary logic (in Kustom formulas)

Mirrors `src/lib/summary.ts`. Four globals feed one text layer:

- **`wet`** — count of days whose forecast icon is rain/shower/storm/snow/sleet/hail:
  ```
  $if(wf(icon,0)="RAIN"|wf(icon,0)="SHOWER"|wf(icon,0)="TSTORM"|wf(icon,0)="TSHOWER"|wf(icon,0)="SNOW"|wf(icon,0)="LSNOW"|wf(icon,0)="SLEET"|wf(icon,0)="HAIL",1,0) + … (days 0–6)
  ```
- **`warm`** — `$mu(round, mu(max, wf(max,0), … wf(max,6)))$`
- **`cool`** — `$mu(round, mu(min, wf(min,0), … wf(min,6)))$`
- **`trend`** — last-3 mean minus first-3 mean of `wf(max,N)`:
  `$mu(round, ((wf(max,4)+wf(max,5)+wf(max,6))/3) - ((wf(max,0)+wf(max,1)+wf(max,2))/3))$`

Summary text:
```
$if(gv(wet)=0,"Mostly dry week ahead.",
   gv(wet)>=4,"Mostly wet week, rain on "+gv(wet)+" of 7 days.",
   "A few wet spells, rain on "+gv(wet)+" of 7 days.")$
 Warmest $gv(warm)$°, coolest $gv(cool)$°.
$if(gv(trend)>=2," Warming toward the weekend.",
   gv(trend)<=-2," Cooling toward the weekend.",
   " Temperatures hold steady.")$
```

## 4. Weather icons

`wi(icon)` / `wf(icon,N)` return enum strings: `CLEAR`, `PCLOUDY`, `MCLOUDY`,
`RAIN`, `SHOWER`, `TSTORM`, `TSHOWER`, `SNOW`, `LSNOW`, `SLEET`, `HAIL`, `FOG`,
`WINDY`, `TORNADO`, `UNKNOWN`. A FontIconModule's `icon_icon` is set by formula
mapping each enum to a built-in Material icon:

```
$if(wi(icon)="CLEAR","wb_sunny",
   wi(icon)="PCLOUDY","wb_cloudy",
   wi(icon)="MCLOUDY","cloud",
   wi(icon)="RAIN"|wi(icon)="SHOWER","grain",
   wi(icon)="TSTORM"|wi(icon)="TSHOWER","flash_on",
   wi(icon)="SNOW"|wi(icon)="LSNOW"|wi(icon)="SLEET"|wi(icon)="HAIL","ac_unit",
   wi(icon)="FOG"|wi(icon)="WINDY","cloud",
   "cloud")$
```

> Prefer purpose-built weather glyphs? Add a weather icon font as a
> FontIcon **icon set** and map the enum to its glyph names instead — see
> Kustom's "Weather Icon Komponent" tutorial.

## 5. Weather function reference (this version of KWGT)

**Current — `wi(type)`**

| Field        | Keyword     |
|--------------|-------------|
| Temperature  | `wi(temp)`  |
| Feels like   | `wi(flik)`  |
| Dew point    | `wi(dpoint)`|
| Condition    | `wi(cond)`  |
| Icon (enum)  | `wi(icon)`  |
| Code         | `wi(code)`  |
| Temp unit    | `wi(tempu)` |
| Humidity     | `wi(hum)`   |
| Wind speed   | `wi(wind)`  |
| Wind unit    | `wi(windu)` |

**Forecast — `wf(type, day)`** (`day` 0 = today)

| Field        | Keyword       |
|--------------|---------------|
| Max temp     | `wf(max, N)`  |
| Min temp     | `wf(min, N)`  |
| Condition    | `wf(cond, N)` |
| Icon (enum)  | `wf(icon, N)` |
| Code         | `wf(code, N)` |

Weekday for day N: `$df(EEE, aNd)$` (e.g. `a1d` = +1 day); today is `$df(EEE)$`.

> Field availability varies by KWGT version and weather provider. If one
> returns blank, open the formula editor's **`fx` → Weather** browser to see
> the exact keywords your install exposes, and adjust.

## 6. Regenerate / customise

The preset is emitted by a script so changes are reproducible:

```bash
python3 kwgt/build_kwgt.py     # writes kwgt/GlassWeather.kwgt
```

Edit colours, sizes, layout, or formulas at the top of `kwgt/build_kwgt.py`
(palette constants and the `build_preset()` function), then re-run. The script
validates the JSON and repackages the `.kwgt` (a ZIP with `preset.json` at its
root plus preview thumbnails).

## 7. Known gaps vs. the web app

- **Hourly chart** — KWGT can't draw an arbitrary smooth line chart, so it's
  omitted. If your provider exposes hourly data you could approximate it with a
  row of height-driven bars.
- **Precip % per day** — Kustom's forecast doesn't reliably expose a
  precipitation-probability field, so the forecast strip marks likely-wet days
  with a dot (from the icon enum) rather than a percentage, and the weekly
  "wet" count uses the same signal.
- **Place name** — uses `$li(addr)$` (device location). Replace with a static
  label or a different location source if you prefer.
- **Alignment** — KWGT vertical stacks align center/right (not left), so the
  card is centered rather than left-aligned like the web mock.
